## 两个物理节点，分别启动什么

当前导航系统按实际设备分为 **2 个物理节点**：

1. **电脑（计算与操作节点）**：在同一台 Windows 电脑上启动 `nomad-campus-api` 模型服务容器、`nomad-campus-rviz` 预览容器，以及 PowerShell 小车操作台。WSL／Docker 是这台电脑上的运行环境，不是额外物理设备。
2. **小车（感知与执行节点）**：车载 ROS 2 运行相机、里程计、API 客户端、本地控制器、安全网关和底盘驱动。这些由操作台管理的小车进程直接运行在车端，不需要把电脑上的两个容器复制到小车。

小车向电脑 HTTPS API 发送选取的图像并接收预测；waypoint 到速度的计算、真实 `/cmd_vel` 发布及运动保护留在小车。操作台另外通过 SSH 管理解锁／停止和心跳，RViz 在电脑本地读取预测快照；预览显示正常不代表小车已执行。

所以，下方“模型服务、RViz、小车操作台”三个启动入口对应的是多个软件组件，不是三台物理设备；ROS 2 软件节点和校园网 AP 也不按新增导航物理节点计数。此处说明部署位置，不代表服务当前已运行。详细边界见[API 地址与职责](../ros2_ws/docs/campus_api.md#地址与职责)。

## Windows PowerShell 启动

### 操作台失联与图像超时是两种不同的恢复

校园 API 操作台新增“停车但保留会话”的重连协议，已于 2026-09-20 晚间成套部署并通过真实 SSH 无硬件断开/重连检查。完整负载及 AP 漫游实车验收仍待现场验证，不将空会话检查当作运动验收。

- **只有图像/API 请求超时**：若已显式开启 `-NetworkPauseResume` 且仍有有效操作台连接，连续挡可以保留行驶意图；车轮零输出等待，满足上述新鲜预测条件后自动恢复。
- **操作台 SSH/心跳失联（默认策略）**：撤销本次行驶授权，取消图像恢复后的自动行驶意图。相机与 API 客户端暂时保留，服务和 RViz 不因操作台重连而重启。SSH 检测到断开时立即请求归零；未检测到断开的链路黑洞由车端最长 2 秒的单调时钟授权期限兜底，不是“失联后零延迟完成物理制动”的保证。
- **操作台恢复（默认策略）**：原终端自动重连原会话，不重放校时、启动或解锁；车辆保持未解锁。重新输入 `i` 查看状态，在现场确认安全后再选择 `t`/`c` 并输入新的 `RUN`。断线前已显示的 RUN 提示和旧确认均失效。
- **等待上限**：正常运行会话失去有效操作台授权后最多保留 120 秒；到期、明确 `q` 或严重进程故障才清理小车进程组，并在确认进程停止后恢复原校时服务。这 120 秒不是允许失联行驶的时间。启动尚未完成时失联不自动重放启动流程。
- **原终端必须保留**：重连凭据只在原操作台内存中。关闭整个终端、电脑重启或会话已过期后，不能从新终端恢复旧 RUN；先确认旧组清理完成再按正常命令新建会话。监督进程被强杀时不能保证自动清理全部后代，须人工检查。
- 默认的已保存密码模式支持后台重连；`-ManualPassword` 的后台连接禁止弹出密码提示，只能使用已配置的 SSH 密钥/agent，避免密码输入与 RUN 提示争抢。

上述默认策略不受速度档或单独的 `-NetworkPauseResume` 影响。需要 SSH/心跳也自动恢复时，必须明确加入下一节的选项。现场物理急停始终保留。

### SSH/操作台心跳也暂停并自动续行（新增，显式启用）

2026-09-20 已成套更新车端六个文件，编译、导入及哈希核对通过。0.05、0.1、0.2 三档隔离 ROS 验证通过；本轮没有启动真实底盘或解锁。完整负载、真实 AP 漫游及物理停车/恢复仍待现场验收。

在 `-NetworkPauseResume` 基础上再加 `-OperatorPauseResume`（Python 对应 `--operator-pause-resume`），仅作用于已经通过 `c` → `RUN` 确认的连续任务，默认关闭：

- SSH/心跳失联仍要求车轮归零，独立最长 2 秒授权期限不变；不允许断线期间沿旧轨迹行驶。
- 原操作台会主动重试连接同一车端会话。自控制器首次进入操作台暂停起，**最多保留 30 秒续行意图**；反复抖动、重新握手以及等待新图像都不延长本次窗口。
- 恢复有效的新连接代次之后，必须收到 **3 个采集时间晚于重连时刻**、原时间戳不同的新鲜预测，并确认相机、模型、里程计正常且车辆停稳，才从零按原加速度限制继续。连接成功或 RViz 出现轨迹本身不是充分条件。
- 窗口到期、`s`/`q`、急停、协议/鉴权异常、解锁回执不确定及原有硬故障取消续行意图。以后必须重新检查并 RUN；定时挡不自动恢复，重启会话也不继承旧 RUN。
- 断线期间输入 `s` 会记下取消请求，重连时先确认取消，再恢复心跳；它不能穿过断开的网络即时送达，需立刻停车时使用现场物理急停。`q` 只尝试停止/清理，不自动续租或重启。
- **30 秒续行窗口**与**120 秒会话保留窗口**不同：前者到期只取消自动续行，后者到期才按清理流程结束小车组；两者都不是允许失联行驶的时间。

`i` 可查看 `operator_pause_resume`、`operator_paused`、`operator_link.connected` 和 `operator_resume_remaining_sec`。`armed=true` 在此模式下可能只表示保留连续任务意图，不能据此认定车轮正在运动。原终端必须保持打开、操作者必须持续现场看护。

1. 输入 `i`，确认状态新鲜、模型 `running`、网关无故障、暂停恢复选项为 true。

## 停止

优先在操作台输入 `s`，完全结束输入 `q`。异常或无法确认停止时立即使用现场物理急停，不依赖校园网。

另开终端可请求逻辑停止（网络和 ROS 服务可用时）：

```powershell
ssh -t -o HostKeyAlias=192.168.0.100 -o StrictHostKeyChecking=yes wheeltec@10.201.207.37 "source /home/wheeltec/nomad_live_control/campus/setup.bash && ros2 service call /nomad/robot_control/disarm std_srvs/srv/Trigger '{}'"
```

小车组结束后，可分别关闭预览和服务：

```powershell
docker stop -t 10 nomad-campus-rviz
docker stop -t 10 nomad-campus-api
```

仅关闭 RViz 不会停车；不能把 GUI 的关闭按钮当作急停。
