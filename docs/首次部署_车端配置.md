# 校园网模式：小车首次部署

配套[根 README](../README.md)第 6 节。这里补齐**新小车从未部署过本项目**时所需的文件、接口和身份登记，不启动底盘、不发送 RUN。不需要在小车安装 PyTorch、下载模型权重或运行 Docker。

本指南只覆盖当前代码支持的厂商 ARM64、ROS 2 Humble/tROS、`wheeltec` 用户、`V550_akm` 阿克曼底盘。不是其他车型的通用自动安装器。已有 `/home/wheeltec/nomad_live_control` 或 `nomad_interfaces_ws` 时，不执行首次复制／登记；先正常退出旧会话、确认停住，再备份并审查升级差异。不要覆盖现有证书、身份或运行记录。

## 1. 先核实厂商环境和硬件

在**小车 Bash，以 wheeltec 登录，不是 root**。先依照厂商说明正常停止自启的 ROS／相机／导航会话；勿盲目 `killall`。软件安装和后续验收应在小车静止、急停有效且有人看护时进行。

```bash
whoami
uname -m
/usr/bin/python3 --version
test -f /opt/ros/humble/setup.bash
test -f /opt/tros/humble/setup.bash
test -f /home/wheeltec/wheeltec_ros2/install/setup.bash
```

预期 `wheeltec`、`aarch64`/`arm64`、Python 3.10，三个 `test` 均成功。厂商系统、`/opt/tros`、底盘/相机驱动**不在本仓库提供**；缺失时先按轮趣与 RDK 厂商文档恢复，不能用空目录或复制电脑的 x86_64 包代替。

安装通用开发依赖（需要小车访问 apt 软件源，sudo 密码由本人输入）：

```bash
sudo apt-get update
sudo apt-get install -y git build-essential python3-colcon-common-extensions \
  python3-numpy python3-opencv python3-pil ethtool \
  ros-humble-rosidl-default-generators ros-humble-cv-bridge \
  ros-humble-image-transport ros-humble-tf2-ros
source /opt/ros/humble/setup.bash
source /opt/tros/humble/setup.bash
source /home/wheeltec/wheeltec_ros2/install/setup.bash
python3 -c 'import rclpy, cv2, numpy; from PIL import Image; import os, signal; assert hasattr(os, "pidfd_open") and hasattr(signal, "pidfd_send_signal")'
ros2 pkg executables turn_on_wheeltec_robot
ros2 pkg prefix turn_on_wheeltec_robot
```

以上 `ros2 pkg` 只检查安装，不启动硬件。必须存在可执行程序 `wheeltec_robot_node` 和该包的 `wheeltec_camera.launch.py`。Python 的 pidfd 接口检查只是初筛，运行前脚本还会检查内核实际支持，不应绕过。

当前代码的硬件约定如下。需结合厂商配置与之后的**相机 shadow／未解锁验收**逐项核实，不要仅为通过检查改名字。

| 项目 | 当前实现 |
| --- | --- |
| 底盘 | `turn_on_wheeltec_robot/wheeltec_robot_node`，`car_mode:=V550_akm` |
| 相机启动 | `ros2 launch turn_on_wheeltec_robot wheeltec_camera.launch.py` |
| 相机输入 | `/camera/color/image_raw/compressed`，frame `camera_color_optical_frame` |
| 里程计 | `/odom`，父 frame `odom`，子 frame `base_footprint` |
| 底盘速度输入 | `/cmd_vel`，只由车端独立网关发布 |
| 静态 TF | `base_footprint` → `base_link`，Z 为 `0.01826 m` |

不同底盘、相机朝向/安装高度、TF、速度方向或里程计比例均需要适配与标定，再做低速验收。模型轨迹和 RViz 不能代替这些检查。

## 2. 登记 SSH 主机密钥

操作台固定使用 `wheeltec@小车当前IP`，但 **`HostKeyAlias=192.168.0.100`** 是现有实现的主机密钥索引别名，不是校园网连接目标。即使 DHCP 地址变化，也按同一个已登记密钥验证这辆车。

先在可信的小车本地终端读取公钥指纹：

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

然后在 **Windows PowerShell**：

```powershell
$RobotIP = Read-Host '填写小车当前 IPv4'
ssh -o HostKeyAlias=192.168.0.100 -o HostKeyAlgorithms=ssh-ed25519 `
  -o StrictHostKeyChecking=ask "wheeltec@$RobotIP" true
```

核对指纹相同后才接受并输入自己的 SSH 密码。不要用 `StrictHostKeyChecking=no` 或未经核对的 `ssh-keyscan` 绕过。若已有该别名指向另一辆车／提示密钥变化，停止并确认设备或系统重装原因；当前默认配置不是多车管理器，不要直接删除冲突条目后盲目接受。

## 3. 获取与电脑相同提交的源码

在 **Windows 项目根目录**先查看并记录提交：

```powershell
git rev-parse HEAD
```

在**小车 wheeltec Bash**，新目录克隆，然后输入上述完整提交 SHA：

```bash
(
  set -e
  git clone https://github.com/Hongtauo/NoMaD_Wheeltec_RDK5.git /home/wheeltec/NoMaD_Wheeltec_RDK5
  cd /home/wheeltec/NoMaD_Wheeltec_RDK5
  read -r -p '输入电脑上的完整 Git 提交 SHA: ' SOURCE_COMMIT
  [[ "$SOURCE_COMMIT" =~ ^[0-9a-f]{40}$ ]]
  git checkout --detach "$SOURCE_COMMIT"
  test "$(git rev-parse HEAD)" = "$SOURCE_COMMIT"
  git rev-parse HEAD
)
```

两端 SHA 必须一致。私有仓库需自己的权限；不要把电脑 SSH 私钥复制到小车。克隆失败或小车无法访问 GitHub，可用已验证 SSH 传输源码归档：在 Windows 项目根目录运行以下替代方案，**只包含已提交代码**。

```powershell
$ArchiveName = 'nomad-source-' + [guid]::NewGuid().ToString('N') + '.tar.gz'
$ArchiveFile = Join-Path $env:TEMP $ArchiveName
git archive --format=tar.gz --output=$ArchiveFile HEAD
if ($LASTEXITCODE -ne 0) { throw '源码归档失败' }
scp -o HostKeyAlias=192.168.0.100 -o StrictHostKeyChecking=yes `
  $ArchiveFile "wheeltec@${RobotIP}:/home/wheeltec/$ArchiveName"
```

然后小车端用 `mkdir /home/wheeltec/NoMaD_Wheeltec_RDK5` 创建不存在的目录，再 `tar -xzf /home/wheeltec/实际归档文件名.tar.gz -C /home/wheeltec/NoMaD_Wheeltec_RDK5`。若目录已存在，先停下确认，勿覆盖。归档无 `.git`，保留电脑 SHA 作为来源记录即可。

## 4. 首次安装文件并在 ARM64 编译接口

以下整块在**小车 wheeltec Bash**执行。使用子 shell，任何一步失败便停止本块，不关闭 SSH；已有部署目录时拒绝覆盖。

```bash
(
  set -e
  test "$(id -un)" = wheeltec
  SOURCE_ROOT=/home/wheeltec/NoMaD_Wheeltec_RDK5
  DEPLOY_ROOT=/home/wheeltec/nomad_live_control
  INTERFACE_WS=/home/wheeltec/nomad_interfaces_ws
  test -d "$SOURCE_ROOT/ros2_ws/src/nomad_navigation/nomad_navigation"
  test ! -e "$DEPLOY_ROOT"
  test ! -L "$DEPLOY_ROOT"
  test ! -e "$INTERFACE_WS"
  test ! -L "$INTERFACE_WS"
  umask 077
  install -d -m 700 "$DEPLOY_ROOT/campus" "$INTERFACE_WS/src"
  cp -R "$SOURCE_ROOT/ros2_ws/src/nomad_navigation/nomad_navigation" "$DEPLOY_ROOT/"
  cp -R "$SOURCE_ROOT/ros2_ws/src/nomad_interfaces" "$INTERFACE_WS/src/"
  for item in robot_operator.py robot_clock.py robot_session_server.py operator_errors.py campus_health.py; do
    cp "$SOURCE_ROOT/ros2_ws/scripts/$item" "$DEPLOY_ROOT/"
  done
  cp "$SOURCE_ROOT/ros2_ws/src/nomad_navigation/launch/robot_bringup.launch.py" "$DEPLOY_ROOT/"
  cp "$SOURCE_ROOT/docker/ros2/robot_control_setup.bash" "$DEPLOY_ROOT/setup.bash"
  cp "$SOURCE_ROOT/docker/ros2/robot_onboard_udp.xml" "$DEPLOY_ROOT/"
  cp "$SOURCE_ROOT/docker/ros2/robot_campus_setup.bash" "$DEPLOY_ROOT/campus/setup.bash"
  cp "$SOURCE_ROOT/ros2_ws/scripts/run_campus_shadow.py" "$DEPLOY_ROOT/campus/"
  source /opt/ros/humble/setup.bash
  source /opt/tros/humble/setup.bash
  source /home/wheeltec/wheeltec_ros2/install/setup.bash
  cd "$INTERFACE_WS"
  colcon build --packages-select nomad_interfaces
  source install/local_setup.bash
  ros2 interface show nomad_interfaces/srv/ArmFor
)
```

成功判据：接口编译成功，显示 `TIMED=0`、`CONTINUOUS=1`、`duration_sec` 以及响应字段。车端 Python 包直接从部署目录导入，无需再 `pip install`；**电脑的 build/install 不能复制到 ARM64 小车**。若中途失败，目录可能部分创建，应检查失败处并修复，不要反复执行首次复制块或删除未知目录。

`robot_onboard_udp.xml` 仅满足基础 setup 的兼容路径；接下来 source **campus/setup.bash** 会清除跨机 DDS 配置。校园网模式不需要旧 External Locators/DDS 中继容器。

## 5. 分发 API 凭据（不传私钥）

先按根 README 第 5 节在电脑创建 API，确认实际 `$ServerIP` 与证书 IP 一致。在 **Windows PowerShell**：

```powershell
$CredentialsDirectory = Join-Path $env:LOCALAPPDATA 'SocialEmbodiedAgent\campus-api'
scp -o HostKeyAlias=192.168.0.100 -o StrictHostKeyChecking=yes `
  (Join-Path $CredentialsDirectory 'server.crt') `
  (Join-Path $CredentialsDirectory 'token') `
  "wheeltec@${RobotIP}:/home/wheeltec/nomad_live_control/campus/"
```

仅适用于上述新建、尚无凭据的 `campus` 目录。随后**小车 wheeltec Bash**：

```bash
chmod 600 /home/wheeltec/nomad_live_control/campus/server.crt \
  /home/wheeltec/nomad_live_control/campus/token
```

目录应为 wheeltec 所有、0700；token 为 wheeltec 所有、0600。不要 `sudo scp`、打印 token、提交凭据，或传输 `server.key`。电脑换 IP、证书到期或轮换 token 时，要停止旧会话并配套更新两端；不要关闭 TLS 校验。

## 6. 为这辆车生成身份与连接配置

身份登记防止因 DHCP 变化而误控另一台机器，不代替 SSH 身份认证。必须读取**这辆车自己的** machine-id、永久 Wi-Fi MAC 和 hostname，不能复制作者或另一辆车的 `identity.json`。

在**小车 wheeltec Bash**先识别实际联网 Wi-Fi 接口，然后填写与电脑证书一致的 IPv4：

```bash
ip -br address
ls /sys/class/net
source /home/wheeltec/nomad_live_control/campus/setup.bash
read -r -p '实际 Wi-Fi 接口名称（确认后填写，例如 wlan0）: ' WIFI_INTERFACE
read -r -p '小车可访问、与证书一致的电脑 IPv4: ' SERVER_IPV4
python3 - "$WIFI_INTERFACE" "$SERVER_IPV4" <<'PY'
import getpass
import ipaddress
import json
import os
from pathlib import Path
import platform
import socket
import sys
from nomad_navigation.robot_identity import (
    CAMPUS_ROOT, permanent_wifi_mac, validate_identity_data,
    require_robot_identity, read_campus_client_config,
)

if getpass.getuser() != 'wheeltec' or os.getuid() == 0 or platform.machine().lower() not in ('aarch64', 'arm64'):
    raise SystemExit('Run as the non-root wheeltec user on the intended ARM64 robot')
interface, server = sys.argv[1:]
address = ipaddress.IPv4Address(server)
if address.is_unspecified or address.is_loopback or address.is_multicast or address.is_link_local:
    raise SystemExit('Enter the reachable Windows unicast IPv4')
identity = {
    'schema': 1,
    'machine_id': Path('/etc/machine-id').read_text().strip().lower(),
    'permanent_wifi_mac': permanent_wifi_mac(interface),
    'hostname': socket.gethostname(),
    'wifi_interface': interface,
}
validate_identity_data(identity)
client = {
    'server_url': f'https://{address}:8443',
    'ca_file': str(CAMPUS_ROOT / 'server.crt'),
    'token_file': str(CAMPUS_ROOT / 'token'),
}
items = [(CAMPUS_ROOT / 'identity.json', identity), (CAMPUS_ROOT / 'client.json', client)]
for path, _ in items:
    if path.exists() or path.is_symlink():
        raise SystemExit(f'Refusing to replace existing configuration: {path.name}')
for path, data in items:
    fd = os.open(path, os.O_WRONLY | os.O_CREAT | os.O_EXCL | os.O_NOFOLLOW, 0o600)
    with os.fdopen(fd, 'w', encoding='utf-8') as stream:
        json.dump(data, stream, indent=2)
        stream.write('\n')
require_robot_identity()
read_campus_client_config()
print('Robot identity and client configuration validated; no hardware started')
PY
```

失败时查看具体错误；配置文件可能已生成，不要通过删除身份/放宽权限绕过检查。代码要求 `identity.json`/`client.json` 为本人所有的普通文件、0600，不接受符号链接。修改 hostname、换网卡／系统会使登记不匹配，需重新核实设备后有计划地迁移，而非照抄旧身份。

## 7. 校时、连通性及分级验收

1. Windows 系统时间应正确；小车已有 ROS／硬件进程先正常退出。按根 README 执行 `start_robot_campus.ps1 -RobotHost $RobotIP -SyncOnly -ManualPassword`。它使用 sudo 设置时钟、核验偏差并恢复原校时服务，不启动 ROS，也不改变时区。需要北京时间显示时，仅在空闲且无会话时自行设置时区；时区不影响 HTTPS 的 UTC 时间判断。
2. 在**小车 Bash**确认健康检查，而不只是 Windows 自测：

   ```bash
   source /home/wheeltec/nomad_live_control/campus/setup.bash
   read -r -p '与 client.json 一致的电脑 IPv4: ' SERVER_IPV4
   python3 /home/wheeltec/nomad_live_control/campus_health.py \
     --server-url "https://${SERVER_IPV4}:8443" \
     --ca-file /home/wheeltec/nomad_live_control/campus/server.crt
   ```

   预期 HTTP 200、`server.ready=true`。这只验证网络/TLS/就绪状态，不验证 bearer token 或持续预测新鲜度。
3. 回到[根 README 第 6 节](../README.md#6-首次接入小车的验收顺序)，运行 45 秒相机 shadow。它才会使用 token 发真实图像，并生成车端唯一报告目录 `/home/wheeltec/nomad_live_control/runs/campus_shadow/`。确认接受结果、帧时间和清理结果正常。
4. 完成后再进入未解锁的正式操作台检查控制器、网关和里程计。**正式操作台会启动真实底盘驱动；shadow 不会。** 最初以 0.05 m/s、短定时、现场急停可用的条件另行确认运动，不将配置成功写成安全验收。

Windows 自动密码填充是可选项：在项目根目录执行 `python .\ros2_ws\scripts\robot_credentials.py --save`，输入自己的凭据并保存到当前用户 Windows 凭据管理器。首次自动填充时才使用系统 .NET Framework 编译 SSH askpass 辅助程序，文件放在用户配置目录，不写仓库。缺少编译器时可先使用 `-ManualPassword`；后台重连仍需要可用的保存密码或 SSH key/agent。`RUN` 始终由现场人员确认，不保存或自动填写。

## 8. 升级与故障定位

- 电脑代码更新不会自动覆盖车端部署副本；相同提交的 Python 包、启动文件、操作台协议和 `nomad_interfaces` 必须配套。升级前正常 `s`、确认停住、`q` 并等待清理，不在线替换运行中的控制代码。
- 不将 `client.json`、`identity.json`、`token`、证书或 `.sessions` 从旧机器人整体复制给新机器人。保留既有数据并逐项审查升级，不重复执行首次登记块。
- `Robot rejected prepare`：先看 Windows `outputs/ros2_robot_operator/console__*/report.json`，检查固定路径、身份/权限、已有 ROS 进程、sudo、时间源；不是无条件重试的网络错误。
- SSH 能连但健康检查失败：核对电脑实际 IP、证书、两端时间、TCP 8443 和校园网隔离。不要用容器/WSL 内部 IP，也不要关闭整机防火墙。
- 有轨迹不走：RViz 是服务器预测，查看操作台 `i` 的授权、暂停原因、车端预测接受情况、里程计及网关状态；不要放宽过期结果控制或绕过独立停车保护。

本指南根据当前代码逐项核对，但没有在另一辆全新厂商小车上执行装机/运动验收。厂商固件、硬件安装与网络差异需要按上述顺序现场复验。
